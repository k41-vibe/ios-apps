**Root / launchd facts found in the iosc deb (matter for later stubbing)**:
- `postinst` does `launchctl bootstrap system /var/jb/Library/LaunchDaemons/com.max.xios.metal-event-broker.plist` (a root LaunchDaemon exposing MachService `com.max.xios.metal-event-broker`; iosc's entitlements whitelist that mach name). `prerm` boots it out.
- `iosc-gl-ent.xml` (entitlements the compositor is signed with): `platform-application`, `com.apple.private.amfi.can-allow-non-platform`, `com.apple.private.skip-library-validation`, `task_for_pid-allow`, `com.apple.system-task-ports`, IOKit user-client classes `AGXDeviceUserClient`, `IOGPUDeviceUserClient`, `IOSurfaceRootUserClient`, `IOSurfaceSendRight`, `IOSurfaceAcceleratorClient`, file exceptions for `/var/jb/`, `/tmp/`, `/var/`, `/private/var/`, mach-lookup `com.max.xios.metal-event-broker`. i.e. it relies on a jailbreak that lets fakesigned binaries carry private entitlements.
- `run-iosc.sh` header: "Runs ON THE DEVICE (root)". It starts `iosc -logical 1440x1080`, waits for `$XDG_RUNTIME_DIR/wayland-0` and `$TMP/xios.json`, then `chown mobile` the `iosc-ddx.sock` rendezvous socket so the **Xios display app (runs as mobile)** can adopt the IOSurface. It also sources `/var/jb/etc/profile.d/xios-pulse.sh` (from xios-audio-server/pulseaudio) if present, but tolerates its absence.
- The iosc control Description says: "Needs the Xios app installed (the on-screen display front end)". That is package `com.max.xios` (492,100 bytes, Depends: firmware, iosc). It is NOT in the requested seed set but nothing shows on screen without it; the xiOS docs also say it is unsigned and needs AppSync Unified. I added it to the closure as an extra seed (see Seeds table).
