## .deb inspection (foot 1.27.0+ios3 and iosc 0.9.47, extracted with inspect_deb.py)

Both debs verified against the index SHA256. Format: `ar` with `debian-binary`, `control.tar.zst`, `data.tar.zst` (zstd, needs the `zstandard` Python module or `dpkg-deb`/`tar --zstd`).

**Prefix**: every path is under `./var/jb/...` (rootless). foot installs to `/var/jb/usr/bin/{foot,footclient}`, iosc installs to `/var/jb/usr/local/bin/{iosc,iosc-client,iosc-input-test,ios-inputd,run-iosc.sh,run-kgx.sh}`, `/var/jb/usr/local/lib/libiosc_egl.dylib`, `/var/jb/usr/local/libexec/xios-metal-event-broker`, `/var/jb/Library/LaunchDaemons/com.max.xios.metal-event-broker.plist`, `/var/jb/usr/local/share/iosc/iosc-gl-ent.xml`.

**Mach-O** (parsed with a Python load-command reader, no otool):
- `foot`: MH_EXECUTE, arm64 (cputype 0x100000c, subtype 0 = plain arm64, not arm64e), `LC_BUILD_VERSION platform=iOS minos=16.0 sdk=16.4`, LC_MAIN, has LC_CODE_SIGNATURE. `LC_RPATH`: `/work/Procursus/build_base/iphoneos-arm64-rootless/1900/var/jb/usr/lib` (build-host leak, harmless) and `/var/jb/usr/lib`. Load dylibs: `@rpath/libiosexec.1.dylib`, `/usr/lib/libSystem.B.dylib`, `@rpath/libepoll-shim.0.dylib`, `@rpath/libpixman-1.0.dylib`, `@rpath/libwayland-client.0.dylib`, `@rpath/libwayland-cursor.0.dylib`, `@rpath/libxkbcommon.0.dylib`, `@rpath/libfontconfig.1.dylib`, `@rpath/libutf8proc.3.dylib`, `@rpath/libfcft.4.dylib`.
- `footclient`: MH_EXECUTE, only links libSystem.
- `iosc`: MH_EXECUTE arm64, minos 16.0, `LC_RPATH /var/jb/usr/lib` and `/var/jb/lib/angle`. Loads `@rpath/libwayland-server.0.dylib`, `@rpath/libxkbcommon.0.dylib`, **absolute** `/var/jb/lib/angle/libEGL.dylib` and `/var/jb/lib/angle/libGLESv2.dylib` (so the `angle` deb must land at exactly `/var/jb/lib/angle/`), plus system `IOSurface`, `CoreFoundation`, `Foundation`, `Metal`, `libSystem`, `libobjc`.
- `libiosc_egl.dylib`: MH_DYLIB, install name `/var/jb/usr/local/lib/libiosc_egl.dylib`, same ANGLE/Metal/IOSurface links.
- `xios-metal-event-broker`: MH_EXECUTE, links only Foundation/Metal/CF/libSystem/libobjc.

**Root / launchd facts found in the iosc deb (matter for later stubbing)**:
- `postinst` does `launchctl bootstrap system /var/jb/Library/LaunchDaemons/com.max.xios.metal-event-broker.plist` (a root LaunchDaemon exposing MachService `com.max.xios.metal-event-broker`; iosc's entitlements whitelist that mach name). `prerm` boots it out.
- `iosc-gl-ent.xml` (entitlements the compositor is signed with): `platform-application`, `com.apple.private.amfi.can-allow-non-platform`, `com.apple.private.skip-library-validation`, `task_for_pid-allow`, `com.apple.system-task-ports`, IOKit user-client classes `AGXDeviceUserClient`, `IOGPUDeviceUserClient`, `IOSurfaceRootUserClient`, `IOSurfaceSendRight`, `IOSurfaceAcceleratorClient`, file exceptions for `/var/jb/`, `/tmp/`, `/var/`, `/private/var/`, mach-lookup `com.max.xios.metal-event-broker`. i.e. it relies on a jailbreak that lets fakesigned binaries carry private entitlements.
- `run-iosc.sh` header: "Runs ON THE DEVICE (root)". It starts `iosc -logical 1440x1080`, waits for `$XDG_RUNTIME_DIR/wayland-0` and `$TMP/xios.json`, then `chown mobile` the `iosc-ddx.sock` rendezvous socket so the **Xios display app (runs as mobile)** can adopt the IOSurface. It also sources `/var/jb/etc/profile.d/xios-pulse.sh` (from xios-audio-server/pulseaudio) if present, but tolerates its absence.
- The iosc control Description says: "Needs the Xios app installed (the on-screen display front end)". That is package `com.max.xios` (492,100 bytes, Depends: firmware, iosc). It is NOT in the requested seed set but nothing shows on screen without it; the xiOS docs also say it is unsigned and needs AppSync Unified. **2026-09-12: dropped from the closure.** XiOSLite's own SwiftUI host is the display front end, so Xios.app is dead weight; worse, it is a nested `.app` bundle under jb/ and LiveContainer's installer picks such bundles up by name, producing a "could not sign these files" warning. It is a leaf package (com.max.xios depends on iosc, nothing depends on com.max.xios), so removing it is safe.
