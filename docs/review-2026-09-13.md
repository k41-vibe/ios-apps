## 0. 一番大きな発見(先に結論)

### 0-1. `ios-inputd` は要らなかった

`wayland/iosc.c:6076-6112 in_dispatch_text()`:

```c
int sent = xios_input_socket_send_improxy(g_input_sock, buf, ...);   /* 入力メソッドの代理が居れば */
fprintf(stderr, "iosc: TEXT %zu bytes -> improxy=%d (0 = local fallback)\n", len, sent);
if (sent > 0) return;
int r = text_input_commit_text(text, len);          /* ← iosc 自身の text-input-v3 で窓に入れる */
if (r == 0) { /* 窓が無ければ 1 バイトずつ keysym に */ }
```

`improxy=0 (local fallback)` は「宛先が無い」ではなく **「iosc が自分で窓に入れる、いつもの道」**。
`ios-inputd.c` の冒頭コメントどおり、あれは **KWin/wlroots 系を入れ子にしたときだけ**の橋渡しで、
iosc の classic セッションには出番が無い。私は `improxy` という語を見て逆に読んだ。

つまり文字が出なかった理由は最初の診断のとおり「文字を受け取る窓が無い」だけだった。
GTK4 のエディタが立てば、**今の直結のままで**文字は入る。

### 0-2. 起動の作法は `xios-session-lib.sh` に全部書いてある

`apps/iosc-desktop/xios-session-lib.sh:1236-1252`(`xios-session app <name>` の実体):

```sh
nohup env \
    XDG_RUNTIME_DIR="$app_runtime" \        # 共有バスの置き場(xios-session-bus)
    WAYLAND_DISPLAY="$app_wayland" \        # ★ 絶対パス($XS_WAYLAND_SOCK)
    DBUS_SESSION_BUS_ADDRESS="$addr" DBUS_SYSTEM_BUS_ADDRESS="$addr" \
    HOME="$XS_VAR/root" \
    "$XS_BASH" -lc "exec $exec" ...
```

`WAYLAND_DISPLAY` は**絶対パス**で渡す設計。だから `XDG_RUNTIME_DIR` を差し替えても
クライアントはコンポジタを見失わない。私が入れたシンボリックリンクの細工
(`Runner.prepareShellBusDir`)は、これを知らずに同じ問題を別の手で塞いだもの。

### 0-3. `libiosexec` の exec は「失敗の種類」で分岐する

`libiosexec/execv.c:23-47 ie_execve()`:

```c
execve(path, argv, envp);                       /* まず本物 */
if (errno != EPERM && errno != ENOEXEC) return -1;   /* ★ それ以外は諦める */
argv_new = get_new_argv(path, argv);             /* #! を読んで sh を前に付ける */
execve(argv_new[0], argv_new, envp);
```

私の `execve` はスクリプトに対して `ENOENT` を返している(`lcsys.c:670-673`)。
そのため `run-shell.sh` や `xios-start-a11y` のような**シェルスクリプトは一切起動できない**。
`ENOEXEC` を返せば libiosexec が `sh script` に書き換えて再挑戦してくれる。

### 0-4. パッケージの postinst を一度も走らせていない

`libgtk-4-1` の postinst は `glib-compile-schemas /var/jb/usr/share/glib-2.0/schemas`。
ipa には `.gschema.xml` が 40 本入っているのに **`gschemas.compiled` が 1 つも無い**。
`wayland-apps.md` の hitori の項に「schema が compile されていないと `g_settings_new` で abort する」と
明記されている。**gnome-text-editor はこのままでは起動直後に落ちる。**
同じく `loaders.cache`(gdk-pixbuf)が無いので SVG のローダーが登録されず、
ドックのアイコンが頭文字になっているのはこれが一因。

## E. 今回の精査で「正しかった」と確認できたもの(触らない)

- **起動の順番** `iosc → ioscbg → ioscbar → ioscdock` は `run-shell.sh` と同じ(壁紙を先に、0.3 秒待つ理由も同じ)。
- **fork のスタック複製**は `sd_launch` の使い方(fork 直後に `setsid`・`setenv`・`execl`)に対して十分。実機で 6KB/74KB の複製が通った。
- **`posix_spawn` → procd**、**`exec` の pid 引き継ぎ**、**`getpwuid` 群**、**`statfs`**、**`fopen$DARWIN_EXTSN` / `close$NOCANCEL` の別名**、**別名の監査**。
- **入力の記録は 32 バイトの `xios_msg`**(`xios_input_socket.c:33`)。文書の「24 バイト」は古い。
- **TOUCH だけを送る**(MOTION を併送しない)— `xios-app.md` 2026-07-30 の「direct touch policy」と一致。
- **改行は `KEY 0xff0d`、後退は `KEY 0xff08`、それ以外は `TEXT`** — `osk-plan.md` の「Return と Tab は key、text ではない」に一致(Tab `0xff09` だけ未対応)。
